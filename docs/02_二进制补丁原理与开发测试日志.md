## 一、 ELF 段映射分析与地址换算准则

通过 `readelf -S ~/.local/bin/agy` 对 ELF 段表核查，确认关键只读数据段与代码段的虚拟地址（`VirtAddr`）与文件偏移（`FileOffset`）关系如下：

| 段名 (Section) | 虚拟地址 (VirtAddr) | 文件偏移 (FileOffset) | 段大小 (Size) | 映射关系 |
| :--- | :--- | :--- | :--- | :--- |
| `.lrodata` | `0x01676b70` | `0x01676b70` | `0x04672a47` | **`VA == FileOffset`** |
| `.rodata` | `0x05ce95c0` | `0x05ce95c0` | `0x00d20a40` | **`VA == FileOffset`** |
| `.text` | `0x06a0a000` | `0x06a0a000` | `0x03cd2510` | **`VA == FileOffset`** |
| `.gopclntab` | `0x0c2ec340` | `0x0c2ec340` | `0x02460fc8` | **`VA == FileOffset`** |

由于 `.rodata` 与 `.text` 的 `VirtAddr == FileOffset`，所有反汇编出的指令地址与字符串地址均可**直接作为文件字节偏移量（1:1 零误差映射）**进行精确修补。

## 二、 核心代码补丁（`.text` 段汇编级改造）

### 1. 解锁 `Bash` 工具调用优先显示中文 `toolSummary`（`0x9b9b78d`，51 字节）

- **所属函数**：`jetski/cli/render/render.toolStepInfo`（入口 `0x9b9ada0`）
- **原版问题**：在 `CortexStepRunCommand` 分支（`0x9b9b77d` ~ `0x9b9b7c0`）中，原版代码直接从 `(%r11)` 读取 `runCommand.CommandLine`（`0x8(%rdx)` / `0x10(%rdx)`），完全忽略了工具调用 JSON 参数中的中文 `"toolSummary"` 字段。
- **补丁设计**：
  利用同包内已存在的辅助函数 `toolSummaryFromMetadata`（`0x9b9ed80`，入参 `%rax = *CortexStep`，出参 `(%rax, %rbx) = summary string`）：
  1. 在 `0x9b9b78d` 直接执行 `callq 0x9b9ed80`；
  2. 检查返回的 `%rbx`（字符串长度）：若非零，则将 `(%rax, %rbx)` 赋给 `(%rsi, %rdx)` 并跳转至 `0x9b9b7c0` 保存；
  3. 若 `%rbx == 0`（无 `toolSummary`），则从栈帧 `0x190(%rsp)` 恢复原 `%r11`，安全回退读取 `runCommand.CommandLine`。

```text

 9b9b792: 48 85 db                 test   %rbx,%rbx
```

### 2. 解除单步思考过程（Thinking）单行 `...` 截断（`0x9ba38a2`，6 字节）

- **所属函数**：`jetski/cli/render/render.stepContent`（入口 `0x9ba2a80`）
- **原版问题**：`0x9ba38a0` 检查 `expanded` 标志位，若未按 `Ctrl+O`，则在 `0x9ba38a2` 执行 `je 0x9ba39d6`（`0f 84 2e 01 00 00`），调用 `collapsedThinkingSnippet` 将思考过程截断为单行 `...`。
- **补丁设计**：将 `0x9ba38a2` 处的 6 字节条件跳转替换为 `90 90 90 90 90 90`（6 个 `nop`），使思考过程始终走完整多行缩进渲染分支。

### 3. 解除折叠工具组 `○ 已思考 Xs (...)` 括号内思考总结的 `...` 腰斩（`0x9b8c779`，5 字节）

- **所属函数**：`jetski/cli/render/render.renderCollapsedToolGroup`（`0x9b8c380`）
- **原版问题**：在生成 `○ Thought for Xs (snippet...)` 时，`0x9b8c779` 调用 `callq 0x9b8b500`（`fitDetailText`），按单行剩余列宽强行把括号内的思考总结截断为 `...`。
- **补丁设计**：将 `0x9b8c779` 的 `e8 82 ed ff ff` 替换为 5 字节 `nop`（`0f 1f 44 00 00`），保留完整的思考总结切片 `(%rax, %rbx)`，交由外层 BubbleTea 容器自动折行完整显示。

### 4. Markdown 自动折行预留 4 列安全右边距（`0x9aaeb20`，23 字节）

- **所属函数**：`github.com/charmbracelet/glamour.WithWordWrap.func1`（`0x9aaeb20`）
- **原版问题**：中文引用块（`> ...`）及中文弯引号（`“”`）存在东亚模糊宽度计算偏差，导致行尾超出视口右边界 1~2 列而发生吞字。
- **补丁设计**：利用 `0x9aaeb2d` ~ `0x9aaeb3f` 的 `0xcc` 对齐填充区，当传入折行宽度 `%rcx > 20` 时执行 `sub $0x4, %rcx`，预留 4 列右侧安全边距。

```text

 9aaeb2e: 48 89 48 20    mov    %rcx,0x20(%rax)
```
