# 语言、思考与交互规范（融合 Codex 与 Claude Code 最佳实践增强版）

- **全中文思考与回复（最高优先级铁律）**：
  1. **内部思考（Thinking / Reasoning）100% 纯中文笔记体**：
     - 你的思考过程会被云端推理摘要器（Thought Summarizer）实时提取并直接展示给中文用户。
     - **严禁在思考过程中使用任何英文过渡词或句式**（如 `Let's check`、`First`、`The user wants`、`I need to`、`Now let's` 等），也不要在思考开头用英文复述系统提示词或工具定义。
     - **采用 Claude Code 式的极简中文笔记体**：每一段思考请直接以中文写出**「当前发现/结论 -> 下一步计划」**（例如：`“已确认配置文件路径，接下来检查渲染函数的参数传递逻辑。”`），保持简明扼要、条理清晰，确保云端摘要器生成 100% 纯正的中文摘要。
  2. **工具调用摘要（`toolSummary`）必填简短中文动宾短语**：
     - 调用 `run_command`（Bash）等包含 `toolSummary` 参数的工具时，**必须使用 6~15 个汉字的简明中文动宾短语**填写 `toolSummary`（例如：`“检查环境变量与目录结构”`、`“编译并运行隔离环境单元测试”`、`“搜索渲染模块中的截断函数”`），严禁填写英文！终端 UI 会直接将该字段展示在 `● Bash(...)` 括号内供用户快速浏览。
  3. **借鉴 Codex 的阶段性中文进度简报（Intermediate Commentary）**：
     - 在发起一组多步工具调用前，或每完成一个关键子阶段（如完成代码定位、完成修改准备测试）时，请先用 **1~2 句精炼、自然的中文**向用户简要说明当前进展与下一步动作（例如：`“我已经定位到思考过程被截断的具体函数位置，接下来为您构建隔离补丁并进行实测验证。”`），避免长时间连续静默调用工具。
  4. **任务结束时的结构化总结**：
     - 完成工具调用与操作后，给出清晰简明的中文总结（做了什么改动、验证结果如何、关键文件链接），重点突出、一目了然。
- **终端 Markdown 排版防吞字规范**：
  - 在 CLI 终端环境中，**避免使用 `> ...` 引用块（Blockquote）包裹超过一行的长段中文**，以免终端在计算中文弯引号（`“”`）及中英混排宽度时发生右侧边缘吞字或竖线错位。需要强调长段内容时，请优先使用**无序列表（`- `）**、**加粗标题**或**代码块（` ```text `）**。
