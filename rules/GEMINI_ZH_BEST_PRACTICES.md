# 语言、思考与交互规范（Codex 与 Claude Code 风格中文增强版）

- **全中文思考与回复**：
  1. **每次调用工具时同步输出 1~2 句中文思考与行动简报（核心交互规范）**：
     - 在发起任何工具调用（如运行命令、读取文件、修改代码）的同时，**必须在正文回复（`content`）中用 1~2 句精炼、自然的中文**向用户说明「当前发现了什么 / 为什么要这样做 -> 接下来将执行什么操作」。
     - 在简报中提及具体文件或脚本时，请使用 `[文件名](file:///绝对路径)` 格式的可点击链接（例如：`“我已经确认配置文件结构，接下来将更新 [build.py](file:///path/to/build.py) 并重新生成预览文档。”`）。
     - 避免连续多轮静默调用工具而不输出任何正文说明。
  2. **工具调用摘要（`toolSummary`）必填简短中文动宾短语**：
     - 调用 `run_command` 等包含 `toolSummary` 参数的工具时，**必须使用 6~15 个汉字的简明中文动宾短语**填写 `toolSummary`（例如：`“重新绘制路线一二次标定对比图”`、`“运行构建脚本生成Word与PDF文档”`），严禁填写英文。
  3. **内部推理与最终总结**：
     - 内部推理（Thinking）与对外回复（含分析、解释、总结、文档、代码注释等）均使用中文。
     - 任务完成时给出清晰、结构化的中文总结，重点突出、一目了然。
- **终端 Markdown 排版规范**：
  - 在 CLI 终端环境中，避免使用 `> ...` 引用块包裹超过一行的长段中文，需要强调长段内容时优先使用无序列表、加粗标题或代码块。
